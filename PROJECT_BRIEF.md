## 1. Что за проект

VR-квест-игра для хакатона **«ИТ-Прорыв», номинация VR/AR**. Кейс — «Научное Золотое кольцо».
Игрок — участник научной экспедиции по городам Золотого кольца. В каждом городе он посещает
объект **научной инфраструктуры**, слушает аудиогид, находит **научный артефакт** и проходит
викторину. Все артефакты в финале складываются в единое целое — «замыкают Научное кольцо».

**Дедлайн: 11.10.2026, 23:59 МСК.**

## 2. Технологии

- **Движок:** Unity **6000.5.3f1** (вся команда строго на этой версии!).
- **Рендер:** URP (шаблон Universal 3D). НЕ HDRP — Quest не тянет.
- **Платформа:** VR, **Oculus Quest 2** (standalone Android).
- **XR-стек:** OpenXR + **Meta Quest Support** (включается на вкладке Android) + XR Interaction Toolkit **3.5.1** (реально установленная версия пакета; неймспейсы XRI 3.x: `...Interaction.Toolkit.Interactables` / `.Interactors` / `.Filtering`) + Input System. Import сэмплы XRI: Starter Assets + XR Device Simulator.
- **Проект:** называется **GoldenRing**, лежит у лида по пути `D:\UnityProjects\GoldenRing`.
- **MCP:** к Unity подключён MCP-сервер **CoplayDev unity-mcp 10.2.0** — через него Claude работает прямо в проекте. Подключение живёт, только пока проект открыт; при обрыве — Window → MCP for Unity → reconnect.
- **Билд под Quest:** Android Build Support (+OpenJDK +SDK/NDK) в Unity Hub; IL2CPP + ARM64; текстуры ASTC; min API Android 10; графика Vulkan; цель 72 fps.
- Известный косметический баг: пакеты показывают "invalid signature" — это баг Unity, не ошибка; НЕ удалять пакеты.

## 4. Игровые механики (полный цикл)

- **Прохождение линейное:** города открываются по очереди. В лобби — карта с городами; сначала доступен только 1-й, следующий открывается после викторины предыдущего.
- **Цикл города (обновлён 29.09.2026):** лобби → выбор города на карте → спавн в городе → робот-гид (EVE) ведёт и рассказывает → игрок находит артефакт (**клеится к левой руке**) → робот подъезжает и предлагает викторину → **сцена викторины**: игрок кладёт артефакт в держатель → викторина активируется → прохождение → игрок забирает артефакт → возврат в лобби → ставит на стенд. Ограничения: в лобби нельзя вернуться, не пройдя викторину; из сцены викторины можно вернуться в город и переслушать гида.
- **Управление:** левая рука — предметы, правая — перемещение (телепорт). Часть викторин — обе руки.
- **Робот-гид (EVE):** белый робот EVE, модель уже в проекте (Assets/_Project/Prefabs/Guide/Robot.fbx). Ездит за игроком по NavMesh, держась на дистанции ~1 м и останавливаясь (не липнет вплотную). Диегетичный UI — на её экране (не плоские панели). Режимы (в проработке): Follow (едет за игроком на общем рассказе), Go-to-exhibit (подъезжает к экспонату, встаёт лицом к игроку; ходьба НЕ блокируется), Pre-placed (уже стоит у экспоната, всегда повёрнута к игроку, начинает рассказ по подходу), Offer-quiz (после находки артефакта подъезжает и предлагает викторину). Точный набор кнопок и глубина поведения — см. DEV_PROGRESS.
- **Локации почти без ручного интерактива:** игрок ходит и слушает объёмный аудиогид; интерактив — только поиск артефакта и викторина. Викторины строятся на том, что игрок физически видел/слышал.
- **Финал (в духе 1 главы Bendy):** все артефакты на стендах → загорается карта с замкнутым Научным кольцом → поднимается раздвижная дверь (как в ТЦ) → финальный тест со статистикой.
- **Повторное прохождение БЕЗ перезапуска приложения:** GameManager делает полный сброс (закрыть города, очистить стенды).

## 5. Архитектура (решено, не отступать)

- **1 город = 1 сцена = 1 объект.** Итого: 9 сцен городов + сцена-лобби + сцена-финал + постоянная сцена-менеджер (additive).
- **Викторины — data-driven:** одна система викторин читает данные точки (вопрос, варианты, тип механики) из ScriptableObject. Наполнять данными можно без программиста.
- **Всё интерактивное — префабы.** Правим префаб, а не копию в сцене (сцены Unity не мёрджатся).
- **Артефакт обязан пережить смену сцены:** факт «какой артефакт собран» хранит GameManager (persistent); физический предмет пересоздаётся по данным в лобби. НЕ полагаться на объект сцены — уничтожится при загрузке.
- **Переходы город↔лобби↔викторина частые:** fade-to-black; лобби/менеджеры в постоянной сцене.
- **Расстановка артефактов на стенды** — через XRI Socket Interactor.

### Структура папок (Assets/_Project/)
Scenes/ (Core, Cities, Quizzes, _Sandbox) · Scripts/ (Core, Interaction, Quiz, Guide, UI) · Prefabs/ (Artifacts, Stands, Guide, Interaction, UI) · Data/ (Cities, Quizzes) · Art/ (Models, Materials, Textures) · Audio/ (Guide, SFX, Music) · Settings/

### Правила командной работы
- Личные/экспериментальные сцены — только в `Scenes/_Sandbox/` с префиксом имени (Eugen_..., Tanya_..., Oleg_...).
- Боевые сцены (в билд) — в Core/Cities/Quizzes, канонические имена, 1 владелец на сцену.
- Никогда двое не открывают одну сцену одновременно.
- Настройки проекта: Asset Serialization = Force Text, Version Control = Visible Meta Files.
- Контроль версий: сейчас передаём проект **архивом** (папки Assets + Packages + ProjectSettings, без Library/Temp/Logs). Это стопгэп — цель перейти на git или Unity Version Control. Внешние пакеты (XR) едут только через Packages/manifest.json, не через унитыпакет.

## 6. Подход к контенту

- Локации почти без ручного интерактива — упор на **объёмный качественный аудиогид**.
- На каждый объект есть документ: описание → что физически на локации → аудиогид по точкам → артефакт → факты для викторины → викторина → **единый текст** (сплошная озвучка для TTS/начитки).
- **Достоверность оценивается жюри** — все факты проверять по официальным сайтам, спорное помечать «требует уточнения», не выдумывать.
- ИИ можно (генерация моделей/текстур/озвучки/кода), но указать в презентации и не 100% ИИ.
